# 清單、卡片與詳情互動

修改清單排序、提醒、卡片、搜尋或 DetailModal 互動時查閱。觀看紀錄與分享規則見 [資料一致性](accounts-and-data.md#觀看紀錄與進度)；變更已播出計算或補查時再讀 [TMDB 與集數資料](tmdb.md#集數計算與補查)。

## 清單狀態與提醒

- `已看 X / Y` 的分母統一使用「已播出集數」，不得回退「已知總集數」。未載入季度、查詢失敗或資料數量不一致，且沒有可用上次分母時，保留已看數並標示「已播出待確認」，不畫猜測的進度條。等於目前分母且沒有漏集警告時用綠色；未看完用淡藍色，漏集警告優先用黃色。
- 「已看完目前已播出集數」在首頁 badge 也視為 `completed`，不能和清單文字打架。
- TV / Anime 若有 `有新集數播出` 提醒，應排在 `正在觀看` 清單最前面。
- 新集數提醒的「今天／幾天前」以 `next_episode_air_date` 的實際播出日計算，不以系統何時發現更新的 `alert_started_at` 計算；舊資料缺少播出日時才退回發現時間。首播提醒則以作品 `release_date` 計算。
- TV / Anime 沿用既有集數掃描入口與共用快取，在清單標題旁顯示精簡提示：掃描進行中顯示「正在確認更新…」、有未讀的新集數 / 首播提醒時顯示發現更新的作品數，掃描成功且沒有更新時顯示「已完成更新檢查」。提示本身不得發送查詢。資料新鮮度由活動期間的六小時檢查週期負責，恢復真正操作時檢查；不得略過快取或新增高頻網路輪詢，也不要混入「已置頂」等實作細節。
- 清單內若同一天有多筆已看紀錄，排序需用最新那筆觀看紀錄的建立時間做 tie-break；後新增的排前面。
- TV / Anime 若尚未播出且使用者還沒有任何觀看紀錄，清單卡片文字顯示「尚未播出」，不要寫成「尚未觀看任何集數」。
- `watchlist_tv_states` 的提醒欄位屬於可持久化的 state / cache，不只是前端記憶體狀態。
- TV / Anime 作品完全移出清單且沒有其他分區項目時，需一併清除該作品的 `watchlist_tv_states`，避免重新加入後沿用舊提醒。
- TV / Anime 若加入清單時尚未播出，首集播出後顯示「已開始播出」並置頂；新集數與首播提醒都在集數清單成功載入後視為已讀並清除，未開啟前持續顯示。
- 新集數與首播提醒只出現在清單，因此只有使用者從清單提醒入口開啟作品，且集數清單成功載入後才標記已讀；從首頁、搜尋、Header 或其他詳情入口查看集數時，不清除清單提醒。
- `season lookup` 失敗沿用既有最多一次重試；TMDB 429／共用冷卻期間不得立即重送，遵守 Retry-After。仍失敗時保留上一輪狀態，顯示「暫時無法確認最新集數」。
- 「即將播出」分頁一部作品可能同時來自兩季：目前正在播、還有未播出集數的那一季，加上下一季已經有集數資料但還沒開播的情況（`src/lib/upcomingEpisodeSeasons.ts` 的 `getUpcomingCandidateSeasonNumbers`）。忽略 TMDB 續訂後先建的空殼季（`episode_count` 是 `null`/`0`），且最多只查最新兩個已知季；這是限制「即將播出」查詢成本的策略，不能據此認定較早季已全部播畢，更不能拿未載入季估算已播出總數。

## 卡片與清單排版

- 卡片保留既有平面背景，不增加陰影或漸層層次；滑入僅輕微位移且尊重減少動態偏好。載入佔位不持續旋轉或閃爍。集數進度使用共用播出日期與一致的觀看計數；允許在原掃描完成後補查缺少的季度，未知分母時顯示待確認並隱藏進度條。不得增加高頻輪詢。
- 卡片採精簡排版：有效集數進度與下一集／集名或已追完狀態並列保留，計數與對應的集數分母標籤同列、細條置底；漏集、資料不完整、載入及上映倒數等重要狀態維持原文，不因精簡而隱藏。不得固定內容高度造成文字裁切。
- 清單標題列在 sm（640px）以上維持單行：左側名稱／筆數／同步與更新資訊，右側清單內找片；標題與提示可截斷、輸入框隨空間縮短，清除鈕置於輸入框內避免擠壓。小螢幕上下兩行，搜尋靠右，不再顯示 TMDB 搜尋範圍說明；不新增請求。
- 已看電影卡片採緊湊排版，兩行片名加上映日、好友列及觀看資訊盡量維持在既有海報高度內；好友列最多 4 個小頭像，其餘用 +人數表示，完整姓名保留在提示與輔助閱讀名稱。觀看資訊單行截斷並保留完整提示，不裁切固定高度、不新增資料查詢。
- 影集／動畫卡片有有效進度時仍須顯示既有 episodeStatus（下一集編號與集名、已看完目前已播出等）；不可為進度條隱藏這些資訊。影集／動畫不顯示上映日，提醒放於片名下方，狀態單行截斷並提供全文提示；保留「已看完」與「已看完目前已播出集數」兩種既有判斷。電影的上映日、「今天上映」與「N天後」倒數不受影響，不新增查詢。
- 卡片進度配色：未看完用低飽和淡藍、已達目前已播出分母用綠色；漏集／集數資料不完整優先用黃色數字及進度條。警告不應單獨阻擋有效進度，沒有可靠分母且沒有上次已確認值時隱藏進度條。同步／更新確認中可保留有期限的上次已播出分母，但必須標示「已播出 · 待更新」；已看數仍使用目前帳號的已同步計數，不能把舊資料當最新。
- 清單內找片只篩選目前已載入的片名，涵蓋分組與即將播出集數；搜尋字詞不可加入資料抓取／同步 effect 相依，不可為搜尋補抓 TMDB。同步提示可縮短但不可把未驗證的本機快取標為已同步。

## 詳情互動

- `DetailModal` 的觀看紀錄好友選擇器在桌面版使用 2 個直向欄位、每欄最多顯示 4 位的網格，超出 8 位後維持容器內垂直捲動；行動版同樣每列顯示 2 位並由外層內容捲動。好友名稱過長時允許截斷，但需保留完整名稱提示。
- 自動刷新詳情彈窗內容時，要保留 history 區塊原本的捲動位置；只限自動刷新，不影響開啟時預設捲動，也不要動畫。
- 電影日期選擇器與 TV / Anime 一樣，使用者正在開啟日期選擇器時要暫停自動刷新，避免選擇器被刷新關掉。
